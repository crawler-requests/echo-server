Capabilities

一次请求，拿到别人拿不到的信号

不只是回显请求头。它把 TLS 层、HTTP/2 层、客户端身份与来源情报一次算清，让你判断「对方声称是谁」与「对方实际是谁」之间的差异。

完整 TLS ClientHello

原始字节、SNI、ALPN、加密套件与扩展全量返回，并计算 JA3 / JA4 / JA4_r / JA4_o。跨 TCP 分片与多 record 拼接，兼容后量子大握手。

per-connection capture

HTTP/2 指纹

SETTINGS 顺序与取值、PRIORITY 帧、伪首部顺序（Akamai 格式）。这一层即使 TLS 被伪装，也常暴露真实客户端。

SETTINGS|PRIORITY|PSEUDO

客户端识别与 UA 伪造

结合指纹库与 User-Agent 给出客户端名称、家族与置信度；当 TLS 与 UA 家族不一致时标记 UA 伪造。

spoof detection

IP 地理与连接类型

国家/城市/坐标与 ASN，并判定 datacenter / residential_proxy / unknown。数据源可自定义优先级链。

multi-provider chain

React 控制台

内嵌在同一个二进制里：日志、大盘、指纹库检索、数据源、IP 链路、审计、通知与 Webhook，开箱即用。

/ui/ · no extra process

Lite 与 Agent

Lite 模式无数据库、只服务 /ip 与 /echo，适合代理池健康检查；内置 MCP，可被 AI Agent 直接调用。

ECHO_SERVER_LITE=1
How it works

四层信号，一条链路算完

服务端在握手与首帧阶段就完成采样，随后与指纹库、数据源链与本地规则融合，最后只返回一个可直接判读的结论。

01

TLS 握手

在 crypto/tls 消费之前 tee 原始字节，捕获完整 ClientHello。

02

HTTP/2 首帧

解析 SETTINGS / PRIORITY / HEADERS，逐连接 HPACK 解码伪首部顺序。

03

身份融合

JA4 指纹库 + User-Agent 交叉验证，输出客户端、置信度与伪造标记。

04

来源情报

按优先级查询 IP 链，给出地理、ASN 与 datacenter / 住宅代理判定。

JA4 家族速览

字段含义
JA3经典 TLS 指纹（MD5）
JA4带版本/SNI/ALPN 前缀，更抗混淆
JA4_rJA4 的原始值版（不哈希）
JA4_o保留扩展真实顺序
JA4HHTTP 层指纹（方法/头集/Cookie）

连接类型怎么判

取值含义
datacenter机房 / 云厂商（代理池、爬虫服务器常见）
residential_proxy住宅代理出口，风控重点
unknown证据不足，不等于一定正常

依据：本地 CIDR 表 + 组织名关键词 + 上游权威标签（配置 Token 后更强）。

Performance

单机 10 万并发连接，零失败

Lite 模式关掉数据库与控制台后，/ip 变成接近内核转发成本的一行响应。下列数字可用仓库内的压测工具复现。

模式并发吞吐失败CPU
lite /ip1,000217k rps0~2 核
lite /ip10,000298k rps0~2 核
lite /ip50,000221k rps0~2 核
lite /ip100,000230k–256k rps0~2 核

10 万并发长连接占用 713 MB RSS（约 7.1 KB/连接）；压测机自身需要 13+ 核，瓶颈在客户端而非服务端。

Quick start

三步跑起来：容器或单文件

镜像已公开发布到 GitHub Container Registry（linux/amd64 与 linux/arm64）， 可直接匿名拉取，无需登录；自带控制台、CA 根证书与 HEALTHCHECK。 不想用容器就下载单文件二进制。下面默认控制台在 :23231、HTTPS 指纹端口在 :23232。

docker run
# 1. 拉取并启动（发布版镜像）
docker run -d --name echo-server \
  -p 23231:23231 -p 23232:23232 \
  -v echo-data:/data \
  -e ECHO_SERVER_ADMIN_USERNAME=admin \
  -e ECHO_SERVER_ADMIN_PASSWORD='换成你的密码' \
  --restart unless-stopped \
  ghcr.io/crawler-requests/echo-server:latest
verify
# 2. 验收（全部应通过）
curl -s http://127.0.0.1:23231/health
# {"status":"ok"}

curl -sk https://127.0.0.1:23232/echo \
  | jq '.client, .client_hello.ja4'

docker inspect --format \
  '{{.State.Health.Status}}' echo-server
# healthy（约启动 15 秒后）

# 3. 浏览器打开控制台完成初始化
http://127.0.0.1:23231/ui/
variants
# 只保留 HTTPS：控制台与 API 走 23232（自签证书）
# 1.0.3 镜像的探针固定探测 23231，这里覆盖成 HTTPS；
# 下个版本起内置探针会自适应，可去掉 --health-cmd。
docker run -d --name echo-server -p 23232:23232 \
  -v echo-data:/data -e HTTP_PORT=0 \
  -e ECHO_SERVER_ADMIN_PASSWORD='换成你的密码' \
  --health-cmd 'wget --no-check-certificate -qO- https://127.0.0.1:23232/health || exit 1' \
  ghcr.io/crawler-requests/echo-server:latest

# Lite：无数据库、无控制台
# 只服务 /ip /echo /health /metrics
docker run -d --name echo-lite -p 23232:23232 \
  -e ECHO_SERVER_LITE=1 \
  ghcr.io/crawler-requests/echo-server:latest
docker compose
# compose.yaml
services:
  echo-server:
    image: ghcr.io/crawler-requests/echo-server:latest
    ports: ["23231:23231", "23232:23232"]
    volumes: ["echo-data:/data"]
    environment:
      ECHO_SERVER_ADMIN_USERNAME: admin
      ECHO_SERVER_ADMIN_PASSWORD: change-me-please
    restart: unless-stopped
volumes:
  echo-data:

# 启动 / 升级
docker compose up -d
docker compose pull && docker compose up -d
  • 镜像 tag 去掉 v 前缀：发布 v1.0.3 得到 1.0.3、1.0、1 与 latest；预发布只发布自身版本号，latest 停留在上一个正式版。
  • 容器以非特权用户 10001:10001 运行。命名卷（-v echo-data:/data）会自动获得正确属主；改为绑定宿主机目录时，先 sudo mkdir -p /srv/echo-data && sudo chown 10001:10001 /srv/echo-data，再挂载 -v /srv/echo-data:/data。
  • Podman 同样可用：把命令里的 docker 换成 podman，参数不变。
  • 不设置 ECHO_SERVER_ADMIN_* 时，打开 /ui/ 会走首次初始化向导创建管理员；第一个创建成功的人拥有整个安装，公网部署请务必先通过环境变量设好密码。
  • 排查用 docker logs -f echo-server；SQLite 落在 /data 卷里，删除重建容器不会丢数据。

不想用容器？单文件二进制同样三步

下载对应平台的压缩包即可，无需 Node、反向代理或外部数据库；控制台与镜像里是同一份代码。

binary
# 1. 下载并校验（以 Linux amd64、<ver>=1.0.3 为例）
BASE=https://github.com/crawler-requests/echo-server
D=$BASE/releases/latest/download
curl -LO $D/checksums.txt
curl -LO $D/echo-server_<ver>_linux_amd64.tar.gz
sha256sum -c checksums.txt --ignore-missing
tar xf echo-server_<ver>_linux_amd64.tar.gz

# 2. 启动（HTTPS :23232 / 控制台 :23231）
ECHO_SERVER_DB=./echo.db \
ECHO_SERVER_ADMIN_USERNAME=admin \
ECHO_SERVER_ADMIN_PASSWORD='换成你的密码' \
PORT=23232 HTTP_PORT=23231 ./echo-server
verify
# 3. 验收
curl -s http://127.0.0.1:23231/health
curl -s http://127.0.0.1:23231/ip
curl -sk https://127.0.0.1:23232/echo \
  | jq '.client, .client_hello.ja4'

# 控制台
http://127.0.0.1:23231/ui/

# Lite：无数据库、只服务 /ip 与 /echo
ECHO_SERVER_LITE=1 PORT=23232 HTTP_PORT=23231 ./echo-server

FAQ

常见问题

部署与判读中最常被问到的几件事。

为什么 HTTPS 端口要用自签证书？›
回显服务要抓到 TLS ClientHello 与 JA4，就必须自己终结 TLS；用自签证书可以开箱即用。生产环境建议换成正式证书或放在反向代理后面，并把明文控制台端口 HTTP_PORT 关掉或仅绑内网（关闭明文端口时的探针覆盖见快速开始的 HTTPS-only 示例）。
JA4 说我是 Chrome，但我其实是 curl，会怎样？›
这正是「UA 伪造」检测的场景：响应里 client.spoofed=true，并说明 TLS 指纹指向哪个客户端。用它来验证你的指纹浏览器 / curl-impersonate 是否真的伪装成功。
connection_type 显示 unknown，是不是说明我的 IP 干净？›
不一定。unknown 只表示本地表与上游都没给出证据，不能当作「住宅 / 正常」的结论。想提高判定率，可在控制台配置更全的 CIDR 数据源，或填写 ipinfo Token 获取权威标签。
Lite 和完整版有什么区别？›
同一个二进制，用 ECHO_SERVER_LITE=1 启动。Lite 无 SQLite、无账号、无控制台与控制 API、不写日志，只服务 /ip、/echo、/health、/metrics。适合对并发与延迟敏感的代理池与探活场景。
数据源（指纹库、CIDR 表）怎么更新？›
控制台「数据源」页支持内置、本地文件、远程 URL 与本地命令四种来源，按优先级合并。远程与命令型可设刷新间隔自动同步，也可手动同步；本地文件在变更时自动重载。
能被 AI Agent 调用吗？›
可以。同一二进制支持 MCP（stdio）：echo-server --mcp。Agent 能查询链、看客户端识别、搜索指纹库、读日志与大盘，签发密码重置令牌需 admin 级凭据。
